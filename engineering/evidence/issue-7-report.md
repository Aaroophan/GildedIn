## Security, privacy, and compatibility decisions

1. **No direct draft-public wiring.** The new semantic server component is a *rendering adapter* only. It must receive the independently compiled, authorized *immutable active release* from Issue 13/14, never raw user JSON or an authenticated user's draft from a public route. Current Issue 5 live-policy public placeholder remains as-is.
2. **No executable content.** User data cannot select React component functions, HTML, JS, arbitrary CSS, executable Mermaid, unreviewed iframe origins, WebGL/shaders, arbitrary fetch/network actions or database queries. Safe rich text is rendered as React text/native nodes. Source inspection is not proof of browser XSS safety.
3. **Same tenant, single CAS.** Ownership and active-account security version are rechecked within the existing transaction before the draft is atomically saved. A failed or replayed mutation cannot append a parallel composition document or alter published releases. No generic database CRUD surface was added.
4. **Least-privilege projection.** A repeater never receives the owner-private raw collection as a prop. The compiler requests Issue 6's approved field projection and strips all unapproved private nested metadata. The source ID manifest contains only emitted eligible public items. Approved media IDs require additional file ownership/release gating; the renderer only accepts reviewed gateway URLs.
5. **A11y semantics.** Native headings/links/tables/accordion elements and stable reading order are implemented. Tabs, carousels, panels and dialogs degrade to readable content without JS, but pointer/keyboard/screen-reader proof on physical browser is **BLOCKED**. The static overflow/occlusion preflight is conservative and not a certification of WCAG 2.2 AA or a substitute for zoom/assistive-tech reviews.
6. **Prior contract preserved.** The Issue 6 built-in profile bindings `displayName`/`identityLabel` are camel-case; the earlier parser incorrectly rejected them as generic field IDs. This was corrected through a **strict three-field allowlist** without relaxing arbitrary schema names. Existing Issue 6 tests stay passing.
7. **Version rollback.** The adapter denies unknown versions and will not guess how to migrate historical node stubs. Real three-release version compatibility remains a publishing test, not a proven result of these local mocks.

## Still BLOCKED / NO-GO

- **Full Next/React/App Router.** The checked-in npm manifest/lockfile lacks the official `next-auth` and `mongodb` install/lock entries from prior milestones. Actual package installation, Next 16 compilation, React 19 server rendering/hydration and real route behavior were not available or executed in this offline environment. No fictitious npm locks/dependency approvals were fabricated.
- **Real persistence:** disposable replica-set transaction isolation, CAS and audits, selected provider free-tier support, unique indexes and live account revocation must be verified. Fakes establish only algorithm behavior under the injected test runner.
- **Browser/assistive technology:** no actual SSR DOM, keyboard/touch, focus-return, 320px/400% zoom, no-JS, reduced motion, actual cookie scope, CSRF, XSS/CSP, dangerous external link or actual wildcard hostname evidence yet.
- **Publication & dependencies:** Issue 10 editor controls, Issue 11 owner preview/autosave, Issue 12 media gateway, Issue 13 activation/versioned releases, Issue 14 real public page and Issue 17 contacts are not implemented here. The presence of a safe renderer must not be treated as publication capability.
- **Carried SPEC-CONFLICT:** HTTP draft `If-Match` stale-change 409 vs standards-based 412 remains an unresolved reviewed interface choice; existing 409 product behavior was retained. See prior Issue 6 evidence and architecture change ledger.
- **Launch:** genuine DNS/TLS/edge headers, zero-cost eligibility, privacy/provider terms, branch protection and source/font licensing still need operator evidence; ADR-031 pending.

**Decision: NO-GO.** Ship only as implementation candidate, not a completed user-facing deployed system. The attached ZIP contains source, all 12 specifications, plan, documentation and reproducible local tests. It does not include personal media, private `.env` or generated dependencies.

# Issue 11 — owned autosave, concurrency, recovery and protected preview contracts

**Authority:** twelve unchanged GildedIn specifications, especially 02 EDT-008/009/010, 03 editor preview, 05 draft model, 06 §11, 07 session/host/CSP and 08 revision/recovery rules, plus plan 11.1–11.10. **Status:** source implementation with synthetic/offline checks; full runtime/security/accessibility gates still BLOCKED. Not a publish protocol or a deployment approval.

## One authoritative, owned draft

- Every mutation is authenticated against the apex, current session/account security version and server-derived owner/portfolio ID; changing a browser's `portfolioId` does not change the effective actor. The canonical document is `drafts`, not React state, an iframe or browser storage.
- The Issue 6 protected `GET /api/v1/portfolios/{id}/draft`, `PUT /draft`, `PATCH /draft`, composition PUT and Issue 10 `PUT /draft/workspace` remain. The workspace mutation accepts **only** the canonical bounded `schemaVersion:1`, `sections`, `nodes`, `contentCollections` shape; the repository merges these fields against the owned draft and revalidates the complete candidate. Owner/portfolio, profile, media approvals, AI permissions and active-release pointer are never accepted from it. The separate Hero editor still uses purpose-specific typed PATCH with explicit manual save and CAS, and has its own route to prevent simultaneous canvas/editor writes from being hidden.
- `PUT /draft/workspace` requires `If-Match: "rev-N"`, `X-Client-Mutation-Id` and existing same-origin CSRF proof. The existing content API responds with `409 CONTENT_CONFLICT` on a stale domain revision; strict HTTP `412` semantics for a literal failed conditional header remain an **OPEN SPEC-CONFLICT-001** and cannot be represented as a resolved release contract. Client recognizes either 409/412 as a conflict but never silently overwrites.
- The Mongo repository runs all checks and the single-document revision CAS in its existing transaction runner. An acknowledged operation records only `{clientMutationId, sha256 fingerprint, revision}` and retains the latest 16 receipts; the current `draftMutationId` is backward compatible. Reusing a token with different request contents is rejected. The receipt history contains no draft bodies or secrets. A ledger entry is *not* an authorization token.
- `GET /api/v1/portfolios/{id}/draft/mutations/{mutationId}` returns an owner-only `{status:'acknowledged'|'unrecognized', revision, acknowledgedRevision?}` with `private, no-store` and `noindex`. It does not return private document content. A missing entry is **unrecognized**, never proof that a write failed. A recognized receipt is only accepted by the client when its saved revision matches the submitted base + 1 and is still the current server revision.

## Browser autosave finite state machine

- `src/domain/editor/autosave.ts` defines `saved`, `unsaved`, `saving`, `uncertain`, `conflict`, `blocked` and a matching `PendingDraftSave` snapshot/token. The controller in `src/ui/owner/canvas/use-draft-autosave.ts` debounces at **850 ms** after edits and admits only **one in-flight mutation**; pressing Save now uses the same flow.
- The payload is captured before the request. Only a matching server ACK advances the known revision and the acknowledged snapshot fingerprint. Edits made while the request is in progress remain **Unsaved** and are scheduled for a later save.
- For dropped acknowledgments, the client first queries the owner receipt endpoint. If current server revision still equals the submitted base and the receipt is unknown, the client may retry **the original payload with the original mutation ID**. Otherwise it blocks for explicit conflict review. Backoff is bounded to 1/2/4 seconds (three scheduled reconciliation attempts), with manual retry available.
- A competing tab saving the same original revision produces one winner. The loser keeps its local edits; the conflict panel fetches an owned server snapshot and shows **category-only differences** (sections, layout, content). The owner can discard/reload or explicitly type `REPLACE` to submit the local workspace as a **new CAS**. There is no unsafe last-write-wins or automatic graph merge. A storage event carries only the new revision, never content.
- `beforeunload` protects unacknowledged work. Unsaved recovery is `sessionStorage` only, in a key scoped to *both* opaque `accountId` and `portfolioId`, max **120,000 bytes**, expires within **24 hours**, and is validated before being offered. It is a convenience, not a backup or an authorization source; browser storage may expose private draft text on shared devices. Sign-out purges local recovery and broadcasts the session end. Session/policy failures stop writes; disabled/terminated portfolio editing and receipt lookup fail closed in the server repository.
- Restoring a browser snapshot based on an older server revision always requires owner review. The user must opt into restoration; no automatic recovery replaces a newer server draft.

## Owner-only preview and validation

- `GET /api/v1/portfolios/{id}/preview?mode=mobile&route=%2F&revision=N&animations=paused` uses the apex authenticated owner, the server-acknowledged draft and `compileComposition({purpose:'owner-preview'})`; no `activeReleaseId` or public-read fallback. Non-owner and tenant-host access is denied. The API sends bounded validated render instructions with ETag, private no-store, noindex, and `Vary: Cookie, Host, Origin`; failures use the shared no-store problem response.
- `GET /dashboard/preview?portfolioId={id}&revision=N&mode=mobile&animations=paused` and its `/owner-preview-frame` subrequest independently check exact owner, host, current portfolio eligibility and draft revision. They provide one semantic SSR renderer in an **isolated same-origin iframe**, with `frame-ancestors 'self'`, `X-Frame-Options: SAMEORIGIN`, fresh CSP nonce and no cross-frame message channel. Other routes remain `frame-ancestors 'none'`/DENY.
- Three mode selectors (desktop 1200, tablet 820, mobile 390 CSS px) render the same draft tree via actual iframe viewport widths so CSS breakpoints apply. Animation is paused by default; owner-triggered Play enables supported non-WebGL composition motion. Three.js stays disabled because the draft is not an approved public-release scene; this deliberately differs from eventual public cinematic delivery. Both iframe and server APIs are `no-store`, `noindex` and always private. Links are **not** shareable bearer tokens.
- The v1 preview **only supports root `/`**. Prospective project detail route previews remain **PARTIAL/BLOCKED** until the full route-manifest compiler in later issues; requests for unknown/traversal/duplicate parameters are rejected, not redirected.
- `POST /api/v1/portfolios/{id}/draft/validate` is CSRF-protected, owner-only and non-mutating. It runs the deterministic release-intent composition/content compiler, semantic/binding and 100 KiB checks, plus current `ready_public` media status rather than trusting media IDs in the draft. Responses contain revision, counts, blockers/warnings and actionable paths; the editor offers a selectable repair target. It **does not** implement Issue 13 publish/activation or prove pixel-perfect overlap detection.

## Verifications and exclusions

Synthetic two-owner fakes and deterministic unit/security fixtures cover one-winner CAS, lost ACK/replay, token mismatch, 16-receipt expiry, unauthorized/disabled reads/writes, recovery scoping/expiry, preview parameter validation and 0 public releases. `npm run verify:issue11:offline` also runs earlier Issues 1–10 regressions, static architecture, secret, lock/license and CI checks. These proofs are **not** substitutes for a real Next build, actual Mongo transaction tier, Auth.js/OAuth/host-only cookie validation, no-JS/Playwright/axe/SR/mobile device testing or CSP/browser checks. No real user or production data is loaded by synthetic tests. `SPEC-CONFLICT-001` and all paid/zero-spend/provider gates remain open. Production **NO-GO**.

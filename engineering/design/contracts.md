# Issue 8 - branded visual system and progressive rendering contract

Scope: GildedIn implementation plan 8.1-8.10, governed by specifications 01-12. This is the implementation contract, **not** evidence of completed browser, licence, CSP, WebGL or deployed-host acceptance.

## Design and security boundaries

1. **Closed, versioned theme grammar.** `src/domain/design/theme.ts` owns `DesignTheme` version 1, dark/light palettes, 14 semantic color keys, contrast validation (4.5:1 for ordinary functional text, 3:1 for focus), allowed font-role selectors, corner presets, scene presets, density and motion. Users cannot provide arbitrary selectors, CSS declaration strings, remote stylesheet URLs, CSS `url()`, scripts, SVG fragments, GLSL or browser event handlers. Server parsing rejects unknown keys before storing the candidate. Validated names alone form scoped CSS custom properties in `ThemeScope`.
2. **Draft-only ownership.** `GET/PUT /api/v1/portfolios/{portfolioId}/draft/theme` uses the existing authenticated apex identity, exact Origin/CSRF guard and owner-specific draft repository. Writes are full-theme replacement, require `If-Match` and `X-Client-Mutation-Id`, and run through the existing transactional revision CAS/idempotent retry. No separate public design CRUD or publication side effect. The previously stored `{preset: ...}` draft remains readable through an explicit safe read-only compatibility path; it is not silently rewritten.
3. **Four typography roles, no unlicensed files.** Display role: Oswald with condensed system fallback; body/editor role: Roboto with Arial/Helvetica fallback. Optional Ink Free accent and Mistral signature are **disabled by default**, including in parsing, until an operator verifies exact web-embedding rights. This source archive includes no proprietary or Google font binaries, no remote CSS `@import` and no `font-face` URLs. Actual loading/rights and font metrics must be proven before signing off 8.2. Font fallback keeps the SSR document readable now.
4. **Native accessible components.** `GiButton`, `GiLink`, `GiField`, `GiSelect`, `GiNotice`, `GiDialog` and `GiTabs` are reusable themed primitives with native labels, errors, focus-visible, >=44 CSS-pixel touch target defaults, keyboard tab switching and native dialog Escape/return focus. `GiTabs` renders every panel without JavaScript; the enhanced client controls may hide inactive panels only after hydration. No drag/hover/scene is required to access essential controls. Real automated axe and screen-reader/manual proof is pending.
5. **Technical corners as decoration only.** CSS-only geometric corner ornament is `aria-hidden`, `pointer-events:none`, never an interaction or focus indication; CSS motion can play on entry/focus/hover under ordinary preferences. The Off visitor setting and system reduced motion suppress the decorative animation; visible focus has independent high-contrast outlines.
6. **Always-readable headline.** The server emits one meaningful full-text `<h1>`/`<h2>`. An aria-hidden individual-letter layer is separate from the heading and its optional Replay button sits *outside* the heading. If JS, Anime.js, storage or animation fails, the full text remains visible and searchable. Session-scoped full-versus-short reveal state is local only; it is not telemetry.
7. **Visual effects are a progressive addition.** `SceneBackdrop` always includes a static CSS grid/gradient. A React.lazy scene module later dynamically imports `three`; the module never fetches drafts/media, executes third-party shaders or intercepts pointer input. It owns one bounded render loop and cancels on hidden tabs/offscreen/context loss/unmount. Four visitor modes are Off/Subtle/Standard/Cinematic. `MotionProvider` enforces OS reduced-motion even when the visitor selects Cinematic, persists preference only in browser storage and does not create a persistent visitor profile. The client has finite scene presets, pixel ratio, FPS and point budgets.
8. **Scene graph comes from verified released public data.** `buildReleasedSceneGraph` is pure, takes a *trusted, server-made*, verified active-release projection only, and requires explicit public AND scene approval on every source. It bounds sources, edges and references to the same release; the output contains stable IDs, category and numeric coordinates, not titles/descriptions, private fields, emails or AI prompts. No data may be read from owner drafts to populate public 3D. **Never accept a browser-provided `activeReleaseVerified` flag as authorization.** When no approved scene graph exists, a content-network preset degrades to an inert decorative grid.
9. **Public release still gated.** `SemanticComposition` consumes only an already validated, live-policy-authorized release plan from Issues 7, 13 and 14. Cinematic enhancement is disabled by default. Existing public routes do not start serving editable drafts or private scene data because Issue 8 exists.
10. **Bundling and licensing are separate gates.** Three.js, Anime.js and `@types/three` exact versions are *candidates* in the opt-in `npm run deps:visual` script; this offline sandbox cannot install/verify them. Do not hand-edit the lockfile or claim a passing Next build. Once connected, audit official package versions, licenses, React 19 compatibility, Next build, actual network requests, chunk sizes, WebGL context handling, axe, Lighthouse, mobile 320px/zoom/reduced motion and browser storage before release.
